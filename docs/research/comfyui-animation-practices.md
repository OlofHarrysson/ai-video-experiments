## Three distinctions that prevent misleading experiments

**A batch is not temporal coupling.** An SDXL latent batch permits several image predictions to be processed together. Repeating an input latent does not add temporal attention, motion training, or a previous-frame dependency. Core `RepeatLatentBatch` also offsets existing `batch_index` values; it does not promise identical noise. In `prepare_noise`, equal noise indices reuse a noise slice, whereas ordinary batched noise draws different slices. Keeping one seed for a batched call is therefore different from separately reseeding each one-image call. [Pinned batching](https://github.com/Comfy-Org/ComfyUI/blob/12d5279438bfefc058a269eae805ceab6047777f/nodes.py#L1304-L1330), [noise preparation](https://github.com/Comfy-Org/ComfyUI/blob/12d5279438bfefc058a269eae805ceab6047777f/comfy/sample.py#L9-L38).

AnimateDiff adds a trained temporal module; Wan/LTX use video-model architectures. That changes what frames can influence one another. A sequence of independently warped anchor images, a recurrent previous-output loop, and a temporally coupled clip are three different experiments even when they accept an `IMAGE` batch. A batch of all future recurrent frames cannot be constructed before those earlier outputs exist.

**There are two clocks.** Film time is the frame index or seconds. Sampling time is the progression through noise levels within one inference. Core `ConditioningSetTimestepRange` and ControlNet `start_percent`/`end_percent` address sampling time, not seconds in the finished film. Advanced-ControlNet separately exposes timestep keyframes and latent/batch-index strengths. A prompt change at film frame 23 is not the same thing as changing conditioning halfway through each frame's denoising. [Core nodes](https://github.com/Comfy-Org/ComfyUI/blob/12d5279438bfefc058a269eae805ceab6047777f/nodes.py), [Advanced-ControlNet scheduling](https://github.com/Kosinkadink/ComfyUI-Advanced-ControlNet/blob/27a67fee80cf46c198b10588a5651f23d67d1e95/README.md#scheduling-explanation).

**An integer seed ramp is not smooth noise travel.** Increasing a seed generates another pseudorandom field; numerical proximity of seeds does not interpolate their tensors. A constant diffusion seed can improve correlation, but may also pin texture to screen coordinates or reduce useful invention. In this loop, `fixed` still leaves pixel noise seeded by base seed + absolute frame. “Freeze the seed” cannot isolate shared noise while that second source changes. These are testable mechanisms, not grounds for declaring the earlier incrementing-seed results invalid. See the [existing seed audit](feedback-parameters.md#the-two-important-distinctions).

## Conditioning, noise and latent reuse

Core `ConditioningAverage` mixes token embeddings and pooled outputs, with special handling for mismatched token lengths; it is not an object-level morph planner. A linear weight path can pass through images with little of the desired structure. For this study, keep shared scene/style language stable and change a concrete part of the scene at each waypoint. Treat this as an artistic hypothesis supported by P01/P06, not an officially prescribed magic prompt. [Pinned operation](https://github.com/Comfy-Org/ComfyUI/blob/12d5279438bfefc058a269eae805ceab6047777f/nodes.py#L94-L132).

The architecture audit reports equivalent destination-length truncation/zero-padding in Difforum's prompt blend. No actual P01 prompt token/chunk lengths have been measured here. Log those lengths and endpoint conditioning shapes before blaming a token-boundary effect; P01/P06 alone do not separate that possibility from changing prompt meaning.

ADE supplies its own prompt scheduling and advanced noise settings; installing FizzNodes solely for a capability already supplied by the chosen graph is unnecessary. FizzNodes remains an available author implementation, but its default-branch commit is from October 2024, so compatibility with this 2026 core should be tested, not assumed from its continued mention in other READMEs. [ADE scheduling source](https://github.com/Kosinkadink/ComfyUI-AnimateDiff-Evolved/blob/9257651221002dcba0a12f9cff37e1944e58fb60/animatediff/nodes_scheduling.py), [FizzNodes](https://github.com/FizzleDorf/ComfyUI_FizzNodes/tree/7d6ea60c55ebd1268bd76fa462da052852bff192).

For shared noise, ADE implements constant, default, repeated-context and FreeNoise variants plus noise-layer combinations. Its `comfy` batch generation and `auto1111` per-latent seed increment modes are explicitly different. A blend needs a defined normalization policy: naively averaging independent unit-variance noises changes variance as well as correlation. ADE includes normalized-sum handling. Do not describe an arbitrary seed list as correlated-noise scheduling. [Noise implementation](https://github.com/Kosinkadink/ComfyUI-AnimateDiff-Evolved/blob/9257651221002dcba0a12f9cff37e1944e58fb60/animatediff/sample_settings.py#L208-L290), [generation modes](https://github.com/Kosinkadink/ComfyUI-AnimateDiff-Evolved/blob/9257651221002dcba0a12f9cff37e1944e58fb60/animatediff/sample_settings.py#L368-L507).

Core `RandomNoise` and `SamplerCustomAdvanced` already separate noise, sigmas, guider and input latent, with sampled and denoised latent outputs. That is useful experimental plumbing, **not proof that retaining latents fixes feedback degradation**. The current warp, sharpening, pixel noise and color correction operate on decoded images. Moving the loop into latent space removes or changes those operations. At SDXL's spatial compression, a latent warp also has a different sampling grid; disocclusion remains unresolved. [Native custom sampler](https://github.com/Comfy-Org/ComfyUI/blob/12d5279438bfefc058a269eae805ceab6047777f/comfy_extras/nodes_custom_sampler.py#L1003-L1096).

A useful diagnosis is 12 repeated encode/decode passes with no denoising, warping, sharpening, pixel noise or color matching, compared with repeatedly decoding the same retained latent and with the original pixels. That can establish whether reconstruction alone causes relevant loss. It cannot establish quality of a changed animation loop. Separately test geometry/effects and denoising if reconstruction is small. Use source images, not compressed MP4 frames, for this diagnosis.

## Temporal modules: practical limits before adding AnimateDiff

The author AnimateDiff repository and Hotshot-XL are older than the maintained Comfy integration. ADE's July 2026 release is meaningful maintenance evidence, but its README still calls AnimateDiff-SDXL beta. SD1.5 motion weights cannot be assumed compatible with SDXL; choosing an SD1.5 temporal route would also replace the current SDXL LoRA/control family. HotshotXL requires SDXL and its matching beta schedule, with an eight-frame sweet spot. Ordinary AnimateDiff examples typically use a 16-frame context. Start with the corresponding window length, not a long sliding-window render. [ADE compatibility notes](https://github.com/Kosinkadink/ComfyUI-AnimateDiff-Evolved/blob/9257651221002dcba0a12f9cff37e1944e58fb60/README.md), [author AnimateDiff](https://github.com/guoyww/AnimateDiff/tree/e92bd5671ba62c0d774a32951453e328018b7c5b), [HotshotXL](https://github.com/hotshotco/Hotshot-XL/tree/cc01f7f82acff985a45f6214152c4a0ba033759f).

Context Options process overlapping sections of the latent sequence through the diffusion pipeline; View Options limit what the motion module sees. Overlap/fusion adds work and does not guarantee seam-free long shots. FreeNoise periodically reuses and shuffles noise across windows; repeated-context noise can cause visible repetition. FreeInit resamples, rather than being free acceleration. These techniques make most sense after temporal coupling has shown an artistic benefit. [Author node documentation](https://github.com/Kosinkadink/ComfyUI-AnimateDiff-Evolved/blob/9257651221002dcba0a12f9cff37e1944e58fb60/documentation/nodes/README.md).

For a source-clip repaint comparison, keep both the module-off and module-on branches in the same batch graph. Comparing the recurrent loop directly with a batched ADE graph changes several mechanisms at once; it is useful for creative selection, but not a clean measurement of the motion module's contribution.

## RIFE and FILM: current evidence and duration traps

There is direct workflow precedent within the existing node ecosystem: the architecture audit found **FlowStabilize → RIFE VFI ×2** in Difforum's `examples/advanced/difforum_parallax_fluid.json`, with 24 source FPS and 48 delivery FPS. Our P01/P06 graphs use neither stage. This is evidence that the author intended a flow/interpolation finishing path, not evidence that its external VFI dependency is installed, that the example executes on our pinned worker, or that stabilizing semantic morphs will improve this art. Test RIFE alone on preserved frames first, then stabilization as a separate variable if a specific instability remains. [Pinned example](https://github.com/chillithebillis/Difforum/blob/1d750efd3c1d1dda792b8ef6c14b06a14a69f879/examples/advanced/difforum_parallax_fluid.json).

Do not substitute higher Difforum cadence for this interpolation test. The classical renderer audit found two maintained/warped endpoints, blending and optional RAFT flow; the current Difforum cadence only forward-warps on skipped frames before the next diffusion repaint. They share a parameter name but not that mechanism. This distinction is companion source evidence, with current-loop semantics also recorded in [feedback parameters](feedback-parameters.md).

Prefer **RIFE as the first interpolation candidate** because its practical author repository has August 2026 activity and the Comfy wrapper has March 2026 activity. Neither commit date proves visual quality. Practical-RIFE's README recommends 4.25 generally and discusses 4.24+ for diffusion-video postprocessing. The pinned Comfy wrapper actually offers `rife47`, `rife49`, `rife417`, `rife426` and a test checkpoint: it does **not** offer 4.25. Begin with a documented stable wrapper option such as default `rife49`, then compare `rife426` on a failing interval; do not relabel 4.26 as the author's recommended 4.25. [Practical-RIFE](https://github.com/hzwer/Practical-RIFE/blob/bbfd2ea90910789a860ea3e2b32a240cd577b75e/README.md).

Implementation inspection matters: the wrapper README's 4.0–4.9 list is stale. Current code handles 4.26 specially, disabling ensemble for it. It also offers precision, task batching and optional compilation. Keep float32, batch size 1 and compilation off for the first correctness comparison; speed claims in code comments are not measurements on our worker. The wrapper installer has its own CuPy/dependency handling, while Practical-RIFE's standalone README says Python ≤3.11, unlike the preserved Python 3.12 worker. These are separate integration routes. [Wrapper source](https://github.com/Fannovel16/ComfyUI-Frame-Interpolation/blob/26545cc2dd95bc3d27f056016300673bdeee78f5/vfi_models/rife/__init__.py), [installer](https://github.com/Fannovel16/ComfyUI-Frame-Interpolation/blob/26545cc2dd95bc3d27f056016300673bdeee78f5/install.py).

At multiplier 3 with no skipped pairs, its output construction yields **(N−1)×3+1** frames. For 48 original frames that is **142**, not 144. The source sample instants span 47/8 = 5.875 seconds; a six-second presentation also includes the last frame's hold. Preserve timing deliberately: at 24 FPS, add two endpoint holds for the six-second comparison. Verify counts and duration from actual output. Interpolate the original 48 PNG frames, not a 144-frame video already containing three copies of each source frame. Do not interpolate across cuts.

**FILM is not a maintained Google candidate:** GitHub reports its author repository archived, with the last default-branch commit January 2023. The existing Comfy implementation uses `film_net_fp32.pt` through `torch.jit.load`, so it is a wrapper/converted-model route rather than Google's original TensorFlow implementation. It remains a possible targeted comparison; source preservation and maintenance classification should be explicit. [Google FILM](https://github.com/google-research/frame-interpolation/tree/69f8708f08e62c2edf46a27616a4bfcf083e2076), [Comfy FILM implementation](https://github.com/Fannovel16/ComfyUI-Frame-Interpolation/blob/26545cc2dd95bc3d27f056016300673bdeee78f5/vfi_models/film/__init__.py).

Artistic hypothesis: interpolation may make popping shapes look like stretching or melting rather than a convincing gradual metamorphosis. Judge contour doubles, holes appearing/disappearing, thin ink-line wobble, and whether visible repainting survives. Smoothness alone is not the acceptance criterion.

## Caching without corrupting conclusions

Comfy caches node outputs based on inputs/change detection. Keep invariant loaders, LoRA application and text encodings reusable during a warm session. However, the recurrent sampler's internal frames are not separate graph nodes: changing its schedule invalidates that node's result rather than providing automatic prefix reuse. Any prefix reuse needs an explicitly preserved continuation state and its known color-anchor semantics. [Execution model](https://docs.comfy.org/custom-nodes/backend/server_overview), [continuation caveat](feedback-parameters.md).

For a repeatability check, identical source pixels from two queued requests are not sufficient if the sampler result came from the cache. Verify actual sampling execution, or use the existing `--cache-none` option in a dedicated future verification session. Do not change the seed to force a “repeat.” The pinned CLI includes RAM-pressure caching, classic, LRU and none; more retained image outputs consume memory, and clearing CUDA allocation cache is different from dropping graph results or model objects. [Pinned CLI](https://github.com/Comfy-Org/ComfyUI/blob/12d5279438bfefc058a269eae805ceab6047777f/comfy/cli_args.py#L138-L143).

Keep approximate denoiser acceleration separate from exact graph reuse. Do not stack compilation, reduced precision, distilled sampling and approximate caches into the first aesthetic comparison. They introduce additional output or startup variables. First measure uncached sampling, warm model inference and total wall time separately; the [parameter study](../../apps/deforum/projects/brain-entity-study/experiments/parameters.md) already shows setup/queue delay can dominate a short experiment.

## Five hypotheses

1. **Prompt-path design remains a content risk.** P06's clarity shows the same recurrent settings can sustain detail; it does not meet the preferred movement. Hypothesis: a richer intermediate description changes the subject while retaining structures that support linework. Compare revised prompt path with P01 first; then test easing separately. Reject if continuity improves only by eliminating transformation, or if midpoint detail still collapses.
2. **High denoise plus changing latent noise may be driving image substitution.** Test fixed versus incrementing diffusion noise first, preserving pixel noise; then independently test pixel noise. Use an identical recomputed short control, then a second seed before a long shot. Reject fixed noise if it merely freezes texture/composition or worsens the preferred motion. Shared-noise mixtures are a later integration hypothesis if the simple comparison supports them.
3. **Presentation judder and semantic discontinuity may be conflated.** Test 3× RIFE on an existing preferred moving clip without rerunning diffusion. It passes only if motion feels more gradual while ink contours and repaint character remain acceptable. If it turns jumps into rubbery warps, more interpolation is not the answer; the generated intermediate content needs improvement.
4. **Motion/time controls are too weak or coupled to support a “model failed at movement” conclusion.** The camera produces only ~4.81% zoom in six seconds. Distinguish an explicit camera-path experiment from semantic morphing, and rescale per-frame transforms if generated FPS changes (`zoom_new = zoom_old^((N_old−1)/(N_new−1))` for equal total advances). Higher generated FPS is not a free smoothing knob at .82 denoise because it adds recurrent reinterpretations. Judge equal-duration, equal-total-transform comparisons.
5. **Architectural upgrades can discard the feature we want.** A latent-only rewrite risks changing geometry/effects; a temporal model risks suppressing surreal repainting and losing SDXL art compatibility. Diagnose VAE-only degradation before a latent rewrite. If a temporal test is warranted, use one compatible ADE window with effect off/on before buying into a larger Wan/LTX path. A successful temporal test must preserve both controlled structure and intentional transformation, not merely lower frame difference.
